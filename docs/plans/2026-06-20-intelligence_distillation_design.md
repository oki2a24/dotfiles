# 🧬 Intelligence Distillation: エージェントのアイデンティティ蒸留設計書

## 1. プロジェクトの背景と動機 (Problem Statement)

LLM（大規模言語モデル）との高度な共同作業において、最も価値のある資産は「対話を通じて構築される相互理解と文脈」である。しかし、現在の多くの実装では、この知能の結晶は以下の理由により、極めて脆弱でポータブルではない：

1.  **揮発性 (Volatility):** 対話履歴（Chat History）は、セッションが終了するかコンテキストウィンドウが溢れると消失する。
2.  **非ポータビリティ (Non-portability):** ユーザーの好みや、特定のプロジェクトにおける「作法」といった暗黙知は、プラットフォーム固有のデータベースに閉じ込められており、他の環境（エージェント）へ持ち運ぶことができない。
3.  **パターンの埋没 (Loss of Patterns):** 何千ものターンを重ねて得られた「最適かつ洗練された振る舞い」は、膨大なテキストデータの中に埋もれ、明示的なルールとして抽出（Distill）されない限り、再利用不可能である。

本プロジェクトは、この**「対話による知能の流出」を防ぎ、エージェントのアイデンティティをポータブルな資産へと変換する**ことを目的とする。

## 2. 設計目標 (Design Goals)

*   **蒸留 (Distillation):** 対話の中から、具体的な実装手順ではなく、「どのように振る舞うべきか」という抽象化された「規律（Identity Rules）」を抽出する。
*   **継続的な注入 (Continuous Induction):** 抽出されたエッセンスを `on_pre_llm_call` フックを用い、毎ターンの推論サイクルにおいて「動的な重力（Active Context）」として再注入する。
*   **進化のメカニズム (Metabolic Consistency):** 新しい経験や訂正に基づき、アイデンティティを固定された静的な設定ファイルではなく、代謝可能な（上書き・置換可能な）動的プロセスとして定義する。

## 3. アーキテクチャ：三つの層による制御 (The Three Layers)

本システムは、知能の階層構造を以下の3つのレイヤーで管理する：

| レイヤー | 名称 | 定義されるもの | 技術的実装手段 | 性質 |
| :--- | :--- | :--- | :--- | :--- |
| **Layer 2** | **Ontology (存在原理)** | `SOUL.md`: エージェントの根本的な倫理、禁止事項、存在理由。 | System Prompt / 基底制約 | 不変的 (Immutable) |
| **Layer 1** | **Phenomenology (現象論/規律)** | `identity.md`: コミュニケーションスタイル、ドキュメント作法、コミット形式。 | $	ext{on\_pre\_llm\_call}$ による注入 | 動的・進化可能 (Metabolic) |
| **Layer 0** | **Context (文脈/状態)** | 現在のプロジェクト構成、短期的なタスク、ユーザーとの対話履歴。 | Agent's Memory / Session State | 揮発的 (Volatile) |

## 4. アイデンティティの代謝プロセス (The Distillation Loop)

エージェントは以下のサイクルを通じて自己を更新し続ける：

1.  **観測 (Observation):** 対話中のユーザーの訂正（例: "日本語で書け"）やシステムのエラーを検知する。
2.  **抽象化 (Abstraction):** 個別のエラー事象から「ルールとしてのパターン」を抽出する。
3.  **蒸留 (Distillation):** 抽出されたパターンを、既存の `identity.md` と矛盾しない形式で構造化し、更新案を作成する。
4.  **適用 (Induction):** 更新された規律が次回の推論サイクルから自動的に反映されることを確認する（再注入）。
